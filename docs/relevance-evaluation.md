# 추천 품질 평가

평가 데이터는 이 저장소를 위해 작성한 **가상 메모 160개**입니다. 사용자 메모를
수집하지 않습니다.

- 개발용 `notes.json`: 20개 주제, 100개 메모. 주제당 기준 메모 2개와 추가 후보 3개.
- 검증용 `validation.json`: 개발용과 겹치지 않는 15개 주제, 60개 메모. 주제당 기준 메모 2개와 추가 후보 2개.

검증용 문장과 정답은 조정 전에 작성했습니다. 개발용 데이터에서 정책을 정한 뒤
고정하고 검증용 데이터를 평가했으며, 검증 결과를 보고 기준을 다시 조정하지 않았습니다.
한영 혼용, 비슷한 표현의 다른 프로젝트·기능, 최대 100일의 시간 차이를 포함합니다.
두 세트 모두 같은 개발 과정에서 만든 가상 문장이라 문체·분포가 비슷하다는 한계는 있습니다.

## 실행

동일 체크아웃에서는 평가·테스트·빌드를 순서대로 실행하세요. Flutter의 공유 네이티브
자산 생성 작업이 겹치면 테스트 로더가 실패할 수 있습니다.

모델 없이 실행하며 네트워크가 필요하지 않습니다.

```sh
NOTEEZ_EVAL_REPORT=/tmp/noteez-keyword.json flutter test test/relevance_evaluation_test.dart
```

검증된 카탈로그 모델을 비교하려면 다음 명령을 명시적으로 실행합니다.
앱과 같은 다운로드·revision·SHA-256 검증 경로를 사용합니다. 임시 디렉터리에
모델을 다운로드하고 평가가 끝나면 제거하므로 앱의 모델 선택과 메모에는 영향이 없습니다.

```sh
python3 tool/check_local_model.py --catalog-model multilingual-e5-small-qint8 --report /tmp/noteez-small.json
python3 tool/check_local_model.py --catalog-model multilingual-e5-base-qint8 --report /tmp/noteez-base.json
```

별도 검증 세트를 평가하고, 모델·토크나이저·데이터 해시가 일치하는 로컬 벡터를 재사용할 수 있습니다.
최초 실행은 검증된 모델로 벡터를 만들며 이후 실행은 모델을 다시 다운로드하지 않습니다.
캐시는 로컬 실험용이며 외부에서 받은 캐시 파일을 평가 근거로 신뢰하지 마세요.

```sh
python3 tool/check_local_model.py --catalog-model multilingual-e5-small-qint8 --fixture test/fixtures/relevance/validation.json --vector-cache .local-dev/small-validation-vectors.json --report .local-dev/small-validation.json
python3 tool/check_local_model.py --catalog-model multilingual-e5-base-qint8 --fixture test/fixtures/relevance/validation.json --vector-cache .local-dev/base-validation-vectors.json --report .local-dev/base-validation.json
```

이미 보유한 호환 ONNX·토크나이저 파일은 다음처럼 지정할 수 있습니다. 이 모드의
출력은 `local-model`이며, 카탈로그 모델의 결과로 간주하지 않습니다.

```sh
python3 tool/check_local_model.py --model /path/model.onnx --tokenizer /path/tokenizer.json --evaluate --report /tmp/noteez-local.json
```

도구는 macOS에서 Flutter 셸 실행기가 ONNX 라이브러리 경로를 잃는 문제를 피하도록
Flutter의 Dart 실행 진입점을 사용합니다. 프로젝트의 ONNX 플러그인 라이브러리만
로드하며 앱 설치나 시스템 라이브러리 변경을 하지 않습니다.

## 지표

- **새 추천 묶음의 쌍 정확도:** 같은 추천 묶음 안의 메모 쌍 중 정답 주제가 같은 비율.
- **새 추천 묶음의 쌍 재현율:** 같은 주제로 라벨링한 전체 쌍 중 함께 묶인 비율. 개발용 200쌍, 검증용 90쌍.
- **기존 묶음 추가 정확도:** 추가 추천 중 정답 묶음에 추천된 비율.
- **기존 묶음 추가 재현율:** 정답 추가 후보 중 올바르게 추천된 비율. 개발용 60개, 검증용 30개.

추천이 0개인 경우 정확도는 `null`입니다. 이를 100%로 표시하지 않습니다.
시간은 토큰화·추론을 제외한 묶음 계산 시간이며, 장비·캐시·실행 순서에 영향을 받습니다.
성능을 비교할 때는 같은 조건에서 cold/warm 실행을 따로 측정해 주세요.

## 개선한 자동 묶음 정책 v2

종전에는 임베딩·키워드·시간 신호를 합친 값을 상한에서 잘라 사용했습니다. 이 때문에
매우 가까운 쌍과 덜 가까운 쌍이 같은 점수가 될 수 있었고, 느슨한 기준으로
서로 다른 주제의 묶음이 합쳐지는 사례가 있었습니다.

새 정책은 원래 코사인 유사도를 보존해 매우 가까운 메모로 핵심 묶음을 먼저 만듭니다.
추가 후보는 핵심 메모 최대 3개와의 평균, 다른 핵심 묶음과의 점수 차이,
현재 모든 구성원과의 최소 유사도를 통과해야 합니다. 확장 단계에서 핵심 묶음을
합치지 않으며, 방금 추가한 메모를 근거로 다른 메모를 연쇄 모집하지 않습니다.

| 모델 | 핵심 쌍 평균 / 최소 | 추가 평균 / 최소 | 다른 묶음과의 최소 차이 |
| --- | --- | --- | --- |
| Small qint8 | 0.94 / 0.92 | 0.88 / 0.88 | 0.01 |
| Base qint8 | 0.94 / 0.92 | 0.88 / 0.88 | 0.02 |
| 미보정 커뮤니티 모델 | 0.96 / 0.94 | 0.90 / 0.90 | 0.03 |

이 값은 확률이 아닙니다. Base는 개발용 데이터에서 다른 주제와의 유사도도 높아
더 큰 점수 차이를 요구했습니다. 모델 revision이나 입력 전처리가 바뀌면 다시 평가해야 합니다.
모델 없는 키워드 추천과 기존 수동 묶음에 대한 추가 추천 규칙은 이번 변경에서 유지했습니다.

### 개발용 100개: 조정에 사용한 데이터

| 모델 | 쌍 정확도 이전 → 이후 | 쌍 재현율 이전 → 이후 | 올바른 쌍 이전 → 이후 | 잘못 묶인 쌍 이전 → 이후 |
| --- | ---: | ---: | ---: | ---: |
| Small | 51.6% → 100% | 31.5% → 42.0% | 63 → 84 | 59 → 0 |
| Base | 36.2% → 100% | 25.5% → 29.5% | 51 → 59 | 90 → 0 |

### 검증용 60개: 조정에 사용하지 않은 데이터

| 모델 | 쌍 정확도 이전 → 이후 | 쌍 재현율 이전 → 이후 | 올바른 쌍 이전 → 이후 | 잘못 묶인 쌍 이전 → 이후 |
| --- | ---: | ---: | ---: | ---: |
| Small | 43.5% → 92.7% | 30.0% → 42.2% | 27 → 38 | 35 → 3 |
| Base | 42.6% → 80.0% | 32.2% → 26.7% | 29 → 24 | 39 → 6 |

Small에서는 오탐과 누락이 함께 줄었습니다. Base는 오탐이 크게 줄었지만
올바른 쌍도 5개 줄었습니다. 남은 오탐에는 같은 제품의 다른 기능이나 영상 편집과
오디오 편집처럼 표현이 비슷한 다른 활동이 포함됩니다. 결과를 보고 이 사례만을
위한 이름·주제 예외를 추가하지 않았습니다.

원본 결과는 `docs/evaluation/policy-v2/`에 있습니다. 각 보고서는 데이터·모델·
토크나이저 SHA-256과 새 정책 버전, 같은 벡터에 종전 기준(0.62 / 0.50)을 적용한
비교 수치를 포함합니다. 그룹 구성원의 ID도 함께 기록해 오탐을 검토할 수 있습니다.

두 데이터 세트는 작고 실제 사용자 메모를 대표하지 않습니다. 개발용 100%를 제품의
일반적인 정확도로 홍보하면 안 됩니다. 평가 테스트는 지표를 출력하며 통과 여부
자체가 추천 품질을 보증하지 않습니다. 알고리즘 회귀 테스트는 점수 상한에 의한 동률,
모호한 후보, 연쇄 확장, 거절 존중, 최대 크기, 모델별 기준을 별도로 검증합니다.

## 긴 메모 처리

512토큰 이내 메모는 기존 `passage:` 입력과 벡터를 그대로 유지합니다.
이를 넘으면 텍스트 블록과 줄 경계로 분리하고, 긴 문단은 접두사와 BOS/EOS를 포함해
512토큰 이하인 창으로 나눕니다. 검색은 문단별 코사인의 최댓값을 사용하고,
메모 간 추천은 입력 토큰 수로 가중 평균한 뒤 L2 정규화한 벡터를 사용합니다.
따라서 문서 뒷부분도 반영되지만, 긴 문서의 작은 주제는 그룹 추천에서 약해질 수 있고
문단이 많은 메모는 검색 최댓값에서 유리할 수 있습니다. 기존 평가 수치를 긴 문서의
품질 보증으로 확대 해석하지 않습니다.

캐시는 기존 모델별 DB 행에 버전이 있는 JSON으로 저장합니다. 정확한 입력 토큰의
SHA-256을 키로 사용해 변하지 않은 문단과 순서만 바뀐 문단은 재사용합니다.
현재 메모에 남은 청크만 저장하므로 편집 이력이 누적되지는 않습니다. 모델 전환 시
캐시를 분리하며 이전 단일 벡터 캐시는 다음 실행에서 한 번 재계산합니다.
짧은 메모 전체가 하나의 청크인 경우에는 편집 시 전체를 다시 계산합니다.
평가용 벡터 캐시와 새 보고서에도 `embeddingPolicyVersion: 1`을 기록하며,
이 버전이 없는 이전 평가 캐시는 다시 계산합니다. 기존 보고서 파일은 당시 결과로 유지합니다.

`test/document_embedding_test.dart`는 끝 토큰 보존, 입력 한도, 캐시 저장·복원,
수정 문단만 계산, 오래된 검색 결과 제외를 검증합니다. 선택 실행하는
`test/embedding_worker_local_test.dart`는 실제 ONNX로 짧은 메모의 동일 벡터와
긴 메모 마지막 문단의 검색 관련성을 확인합니다. 로컬 모델 smoke test는
카탈로그 Small/Base의 새 품질 평가를 대체하지 않습니다.

## 추천 정책 v3: 기존 묶음 밖의 메모 보완 (2026-09-05)

현재 기본 Small 모델에만 추가 단계를 적용합니다. v2로 만든 묶음은 그대로 보존하고,
남은 메모에서 서로가 최근접인 쌍을 찾습니다. 코사인 0.90 이상이며 양쪽 모두
차순위와 0.01 이상 차이가 있어야 시작점이 됩니다. 비교 대상에는 이미 묶인 메모도
포함합니다. 이어서 원래 시작점에 대한 평균 0.88, 다른 묶음과 차이 0.01,
모든 구성원과 최소 0.88을 만족하는 메모만 추가합니다. 새 구성원은 다른 메모를
모집하는 근거가 되지 않으며, 기존 묶음은 경쟁 대상으로만 사용합니다.
최소 3개가 모인 경우에만 추가 묶음을 제안합니다. 약한 두 메모의 관계 추천은
기존 관계 UI에서 확인할 수 있습니다. Base·미확인 모델·키워드 경로는 기존 기준입니다.

`work-notes.json`은 사용자가 가져간 합성 업무 메모 50개를 실제 Markdown 가져오기
코드로 변환한 블록입니다. 체크리스트와 제목을 포함하며 사용자 DB를 추출하지
않았습니다. 8개 업무 주제 외의 독립 메모 6개는 각각 별도 라벨로 처리합니다.
기존 개발용 100개와 이전 검증용 60개는 이번에는 모두 개발/회귀 데이터입니다.
`recommendation-holdout.json` 44개(새 업무 주제 10개 × 4개, 독립/혼합 메모 4개)는
점수 확인 전에 작성·고정했습니다. 정책을 고정한 후 한 번 평가했고 그 결과로
기준을 다시 조정하지 않았습니다. 각 SHA-256은 `policy-v3/*freeze.txt`에 있습니다.

| 데이터 | 묶음 v2 → v3 | 올바른 쌍 v2 → v3 | 잘못 묶인 쌍 v2 → v3 | 재현율 v2 → v3 |
| --- | ---: | ---: | ---: | ---: |
| 업무 예제 50개 | 0 → 3 | 0 → 27 | 0 → 0 | 0% → 27% |
| 기존 개발 100개 | 19 → 20 | 84 → 87 | 0 → 0 | 42% → 43.5% |
| 기존 검증 60개(현재 회귀용) | 14 → 14 | 38 → 38 | 3 → 3 | 42.2% → 42.2% |
| 새 검증 44개 | 0 → 4 | 0 → 12 | 0 → 0 | 0% → 20% |

업무 예제에서는 한빛 도입 6개, 검색 성능 4개, 사무실 환경 4개가 추천됩니다.
아직 모든 주제를 찾아주지는 못합니다. 기존 검증의 오추천 3쌍도 해결되지 않았습니다.
새 검증 역시 같은 작성자의 짧은 합성 메모이며, 실제 사용자나 긴 문서의 정확도를
보증하지 않습니다. 다음 조정에서는 이 44개도 회귀용으로 전환하고 새 검증이 필요합니다.

모든 Small 벡터는 검증된 카탈로그 모델과 현재 임베딩 정책으로 계산했습니다.
이전 버전의 벡터 캐시에 버전 번호만 붙여 재사용하지 않았습니다. 상세 결과는
`docs/evaluation/policy-v3/`에 있고, `previousPolicyClusterPairs`가 동일 벡터의 v2
비교입니다. `baselineClusterPairs`는 더 오래된 v1 비교이므로 혼동하지 마세요.
`test/support/automatic_clusters_v2.dart`는 수정하지 않는 이전 정책 비교용입니다.
고정된 합성 메모의 코사인 점수로 일반 테스트에서도 네 데이터 세트의 회귀를 검사합니다.

평가 재현(첫 실행은 검증된 모델 다운로드):

```sh
python3 tool/check_local_model.py --catalog-model multilingual-e5-small-qint8 \
  --fixture test/fixtures/relevance/work-notes.json \
  --vector-cache .local-dev/small-work-vectors.json --report /tmp/work-report.json
```

이미 받은 모델을 쓰려면 `--installed-directory '/모델/디렉터리'`를 추가합니다.
`model.onnx`와 `tokenizer.json`의 해시를 카탈로그와 대조하며 설치 상태는 변경하지 않습니다.
